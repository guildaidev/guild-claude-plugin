# Timeline generation: integrated overhead reductions

These changes reduce deterministic preparation and serialization work. They do
not change the author/copy/factual roles, model defaults, two copy dispatches,
three display repairs, genuine reviewer judgments or source/security boundaries.
Normal current snapshots still use the one packaged review UI; private review
quality is not a render-approval token. No observer is installed or restored.

## Actual workflow

1. After native completion, package already-collected application-emitted session
   records with `inspect.mjs postrun-package INPUT NEW_BUNDLE NEW_PROJECTION`.
   Supply the original application/scenario/target metadata, exact emitter
   identities and a per-executed-operation coverage plan. The packager does not
   invent that plan, classify business success or obtain a source read.
2. Author a closed draft and assemble it normally. Before **each** current copy
   claim, run `preflight-source CANDIDATE ORIGINAL_BUNDLE NEW_REPORT`, inspect its
   private authored-field locations, then use
   `claim-copy CANDIDATE STABLE_BUDGET ORIGINAL_BUNDLE CURRENT_REPORT`.
   Unsupported literals are assistance, not proof of falsity or a new approval
   gate. There is no automatic edit, extra model dispatch or refunded claim.
3. `packet-copy` and `packet-fact` produce readable lossless compact packets.
   `packet-copy-full` and `packet-fact-full` retain the original full format.
   Every text, source payload, routing decision and required judgment remains
   available; compact responses replace repeated identities with exact bound
   references, not inferred findings or timestamps. Small packets can grow.
4. Await the genuine final response. For the observed native hand-back format,
   serialize explicitly exposed complete child/parent records with
   `packet-handback CHILD_JSONL PARENT_JSONL NEW_CAPTURE`, then run
   `capture-native-copy|capture-native-fact CANDIDATE CAPTURE NEW_REVIEW BINDING
   [EXACT_PACKET]`. The retained binding must match native parent, child,
   dispatch, prompt, final receipt and current candidate. Unknown formats fail
   rather than causing repeated capture or a formatting-only review dispatch.
   The old explicit completed `end_turn` transcript format remains supported.
5. A full genuine compact JSON response can instead be saved unchanged and
   expanded with `expand-review CANDIDATE WIRE_REVIEW EXACT_PACKET NEW_REVIEW`.
   Both capture paths expand references deterministically, run the existing full
   validators, and write only a new private file. Invalid feedback remains
   invalid; no approval is fabricated.
6. The factual packet includes a private source-navigation index. Its claim,
   event, artifact and operation maps help locate sources, but reading the index
   or the cached candidate is **not** an independent source call. The checker
   retains its existing read-only allowlist and must obtain genuine read clocks.
   Guild `from_id` means events **after** that ID, not older-event pagination.
   Unreachable history, truncation and unavailable clocks remain explicit limits.
7. Finalize and render normally, preserve the current target and present its
   actual artifact. A successful file parse or process exit is not proof of
   dispatch, source truth, browser presentation or user acceptance.

All commands above are direct Node invocations of the packaged `inspect.mjs`.
They do not call models, integrations or application mutation tools. Native host
dispatch and authorized independent source reads remain separate responsibilities.

## Correct artifact differences

Content-free mutation acknowledgments are valid records, not missing content.
They must remain in sequence so genuine observed empty, first-content and later
states can form a continuous source-bound comparison. An unresolved creation
target is allowed only through the explicitly guarded **non-material** binding;
it is never an alias proving an observed artifact identity.

Source chronology retains submillisecond precision. Millisecond occurrence
bounds are rounded outward rather than backdating an observation. Equal or
backward source order still fails. A genuine empty baseline remains internal
source data instead of an empty public card; its later additions are green, and
clearing nonempty content still shows red removals. Missing baselines are never
invented from a creation request, acknowledgment or final document.

## Header and scrolling

Prompt count and review controls are in the application header. The fixed bottom
bar and its reserved space are gone. Ordinary document scrolling works over the
header, queue, event column and surrounding page. Narrow or tall headers are not
made sticky when doing so would hide content. Native dialogs and textareas can
still scroll where needed. Existing manual feedback identity, ordering, technical
fix bytes, keyboard access, local Dismiss and copy/paste boundaries remain.

## What has and has not been measured

The earlier estimates—roughly four to six minutes combined—came from one
historical 14m30s run. They are not measured native improvements. Local tests can
prove deterministic round trips, preserved judgments, source chronology and
browser behavior, but not equivalent model behavior or a new end-to-end latency.
Native/application reruns and CLI reloads require separate authorization.

Detailed contracts and bounds are in the packaged references:
`source-grounding.md`, `postrun-package.md`, `review-codec.md`,
`review-capture.md` and `source-navigation.md`.

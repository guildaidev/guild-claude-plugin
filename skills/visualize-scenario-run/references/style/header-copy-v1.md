# Header copy product policy 1.0

Applies only to snapshot 1.7 `header_copy`, separate from SDLC v2 and the selected
style guide. The packet supplies the executable closed schema and policy. These
are product/UI budgets, NOT ASD sentence-length limits on Economist copy.

- HEADER-1 `application_name`: one or two plain job-oriented words. This is a
  display name, not an invented official identity. Keep exact agent IDs/names in
  original context and source-backed timeline sentences.
- HEADER-2 `workflow_purpose`: one brief why statement, at most 120 Unicode code
  points AND 16 whitespace-separated words. Preserve the full intended effect
  in `workflow.intended_world_effect`, not in this subtitle. Never truncate it.
- HEADER-3 `scenario_name`: at most six plain distinguishing words about the
  starting situation and supported result. Do not imply success for unknown,
  attempted, partial or failed outcomes.
- HEADER-4 `starting_context`: explain the relevant initial situation or requested
  task in human terms. Do not invent a sender, unobserved absence or trigger.
- HEADER-5 `observed_result`: explain what the evidence establishes at the end,
  preserving uncertainty, failure, conflict and source scope. A request is not
  delivery; run completion is not world-effect success or human readership.

Across the last two components use two or three plain sentences elaborating the
scenario name. The validator requires nonempty components, not brittle punctuation
counts. All five authored strings are reviewed, field-hashed and candidate-bound;
`claim_refs` binds the whole header to nonempty existing claims whose sources the
independent factual checker must actually assess. The script checks references,
not whether the claims cover the words truthfully.

Use Economist for this human-experience copy, then SDLC v2 and this product policy.
Do not stack ASD or use “Economist has no ASD target” to ignore UI budgets. For
unclear meaning return unresolved/blocked rather than an invented outcome.
Product findings use `rule_group: header_copy` and the matching HEADER rule ID.
Include `rule_versions.header_copy: "1.0"` on the final 1.7 copy review. Neither
numeric validity nor a copy pass is independent factual or user approval.

The author must supply a closed draft 1.1 with explicit header_copy before the
first copy claim. The assembler copies, never invents or applies suggestions.
It preserves all original workflow/scenario specification fields. Invalid header
budgets fail preflight/claim-copy before consuming either immutable dispatch claim.
At most two copy iterations remain: after a valid second nonpass display the exact
text and real findings, not a forced pass or a third review. Factual/stale/malformed
checks still apply. Legacy 1.0–1.6 retain their own contracts and words; never add
this policy to old reviews or imply a presentation-only rerender ran it.

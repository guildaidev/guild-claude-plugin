# Header product policy 1.1 — general scenario description

Current snapshot 1.8 / closed draft 1.2 replaces the two run-description components
with `header_copy.scenario_description` and nonempty `description_claim_refs`.
Legacy 1.7 remains its original contract; never relabel its two components.

HEADER-1 application_name: one/two words. HEADER-2 workflow_purpose: <=120 Unicode
code points AND 16 words. HEADER-3 scenario_name: <=6 words. These remain authored,
source-grounded display text, not invented official identities or success claims.

HEADER-4 scenario_description is a BRIEF GENERAL PRESENT-TENSE summary of the
scenario setup/task and intended behavior. Prefer ONE concise sentence; two only
if truly needed. Product budget: <=200 Unicode code points AND 30 whitespace words.
It is NOT what happened in a particular run. Never combine a past-tense starting
context with an observed result, describe “this simulated run”, or add reliability,
source-review or generation-process disclaimers. Actual run outcomes/status,
uncertainty and source observations stay in their existing run/timeline locations.
The reviewer assesses tense/meaning; numeric validation does not pretend to parse
English tense or count sentence punctuation. Use Economist, then unchanged SDLC v2
and this product policy, not ASD. New descriptions and references bind both reviews.

For an explicitly authorized description-only refresh, read the exact last reviewed
snapshot and matching evidence packet. The author receives a closed narrow packet
and emits ONLY schema_version 1.0, scenario_description and existing claim_refs,
once. Cache every other authored/business string, source/artifact byte and reference
exactly. No broad author pipeline, hidden rewrite, suggestion application, second
generation or correction is allowed. Invalid generation stops. Reviewers may check
the unchanged full candidate and cite historical passage provenance, but must issue
genuine matching whole-candidate checks, preserving existing unresolved findings
and source limits. Never restamp a historical whole-candidate digest. One stable
exclusive generation claim survives resumes; genuine copy budget claims are new
and distinct from the retained historical invocation. At most two copy checks,
without revising text, retain the existing valid-second-nonpass policy internally.

ABSOLUTE PUBLIC RULE: generation machinery is private. Never show editorial/factual
review records, reviewer identities/models, iterations/verdicts, rule versions,
pipeline findings or candidate/schema/digest metadata in UI, evidence panels,
dialogs, cart or copied prompts. No nonapproval/iteration notice. Preserve genuine
internal records and every stale/role/source/factual gate; no fake pass. Display
business outcomes and source uncertainty in human terms, not reviewer prose.

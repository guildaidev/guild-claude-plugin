# Finish with the normal packaged HTML

Use ONE renderer and ONE full UI. There is no limited-evidence mode, alternate
layout, handcrafted fallback HTML or reduced composer. Once bounded editing ends,
the content is good enough: render it with the normal packaged shadcn UI, cart,
dialogs, source-backed diff and strict offline CSP. Never expose generation
machinery or a nonapproval caveat in public HTML, source panels, chat or prompts.

Read completion.md for native waiting and exact-target presentation and progress.md
for immediate loading feedback. Real authorization, access and local host limits
remain. The all-current-scenarios technical-error exception still produces no
visualization; it does not authorize extra writes or unbounded application retries.

## Current source-bound contract

Author closed draft **1.3** and assemble snapshot/candidate **1.9** from the original
sanitized bundle 1.0. Assembly retains that bundle privately in `source_bundle`.
The renderer validates closed content shape, references, header budgets, immutable
source fields, escaping and safety independently of editorial review judgments.
Historical 1.0–1.8 inputs retain their original read-only contracts and strict
review bindings. Never downgrade, relabel an old snapshot or restamp reviews.

Review records are OPTIONAL PRIVATE diagnostics, not render permissions. Save the
actual responses unchanged, even revise/blocked, incomplete or malformed responses.
`inspect.mjs copy` and `fact` still reject invalid records. A stale or invalid record
is never treated as valid, never confirms an outcome and never supplies public
qualifications. Missing factual feedback is not an invented source read or pass.
Known business conflicts/uncertainty must remain qualified in the authored story
and supplied source coverage. A tool acceptance is not delivery; current state is
not causation; execution completion is not business acceptance. An unknown version
stays unknown. Do not assert unsupported success.

## Bounded quality work

- At most TWO copy-review calls, including failed/resumed/corrective calls, with
  the SAME stable immutable budget claims. No reset, refund or third dispatch.
- Preflight all prose, source scope and meaning before dispatch. After the first
  response, explicitly apply safe author corrections if needed and use the remaining
  second iteration. Never autoapply suggestions or edit a reviewer's judgment.
- Await actual native final completion sequentially: copy, then factual checking.
  A launch receipt is not final feedback. Do not poll files/transcripts or sleep.
  A completed malformed/out-of-inventory copy response does NOT block facts or HTML.
  Unavailable/failed factual response does NOT block normal HTML either. Preserve
  genuine diagnostics privately; do not ask the user to debug generation.
- After the second copy response, stop copy polishing. A known factual error may
  receive one bounded source-grounded author correction/qualification. Any content
  change invalidates BOTH reviews; discard their authority, not their historical
  files. No fresh model dispatch merely to escape exhaustion. Only display.compact
  can reuse an unchanged matching pair. Reaching the budget is good enough.
- Keep at most THREE shared check/render attempts. Structural/source/security
  errors still require actual repair within that bound; do not weaken them, falsify
  source fields or switch layouts. A real file/runtime/authorization impossibility
  is reported honestly with any safe link, not concealed by invented HTML.

## Finalize and render

Use new private files in the approved invocation directory:

```sh
node /absolute/skill/scripts/inspect.mjs finalize CANDIDATE NEW_SNAPSHOT COPY_RECORD_OR_- FACT_RECORD_OR_-
node /absolute/skill/scripts/render.mjs NEW_SNAPSHOT NEW_HTML
```

`finalize` accepts only source-bound 1.9 candidates. Optional JSON records remain
unchanged; unreadable/non-JSON files remain in their original private files and
produce private diagnostics. No script fabricates approval. The normal renderer
classifies matching valid records privately and ignores invalid/stale records for
public evidence/status. It derives cart identity from the actual final content,
not a fictitious factual pass. Preserve all originals and consumed claims.

Publish the exact final snapshot/HTML through progress.mjs `ready`; it validates
source/content, exact target identity and deterministic renderer bytes, not a fake
pass. Present once under hosts.md and give the durable direct artifact link. No
application iteration may run in parallel with finishing the page. Late output
for a superseded target stays historical, never automatically replacing delivery.

Normal HTML delivery does NOT establish review approval, scenario acceptance or
authorize application changes, reruns, external writes, cleanup, publication or
release. Keep the delivery gate until observed presentation/user confirmation or
explicit cancellation/supersession. Do not silently downgrade permissions/credentials.
Ask only a necessary real access/host/user-owned question, not a reviewer choice.
